## 1. 背景与目标

### 1.1 背景

ITCodeX 已在 `server` 落地动态元数据引擎（类 NocoBase 的低代码数据建模）：

- 运行时创建 / 修改 / 删除数据表（Collection）和字段（Field）
- 8 大类 Interface 字段、CEL 校验、关系、索引
- 业务记录标准 CRUD（`/api/c/:collection`）
- Yaegi 钩子与自定义 API

后端能力已具备，但缺少可视化管理界面。管理员目前只能通过 HTTP 调用完成建模和数据维护，学习成本和操作成本高。

### 1.2 产品一句话

为 ITCodeX 元数据引擎提供一套**现代、桌面优先**的管理端：用可视化方式建表、配字段、管记录，全部能力对接现有 `server` API。

### 1.3 目标

| 编号 | 目标 | 成功标准 |
|------|------|----------|
| G1 | 可视化建模 | 管理员无需手写 JSON，即可完成建表、加字段、配校验、建索引 |
| G2 | 可视化管数据 | 按表结构自动生成表格 / 表单 / 详情，完成记录增删改查、筛选、排序 |
| G3 | 关系可操作 | 在记录中选择、追加、替换、解除关联，并支持 appends 展示 |
| G4 | 校验可配置 | 内置规则可视化配置；CEL 表达式有编辑器、模板和错误提示 |
| G5 | 二开可管理 | Yaegi 脚本可视化管理：钩子、自定义 API、语法校验、启用禁用 |
| G6 | 只消费现有 API | 前端不自建后端、不新增业务接口；全部走 `server` 已暴露路径 |

### 1.4 非目标（本产品明确不做）

与后端设计方案范围对齐，管理端**不实现**：

| 不做 | 说明 |
|------|------|
| 后端服务 | 不开发新 API、不代理业务逻辑、不落库 |
| 独立账号 / 权限 / 角色 | 后端无用户体系；`createdBy` / `updatedBy` 由请求上下文注入 |
| 页面搭建 / 区块编排 / 工作流 | 不属于元数据模块 |
| 视图表 / SQL 表 / 继承表 / 外部表 | 后端 v1 不做 |
| 完整对象存储引擎 | 文件表只管理元数据；上传后端另议，本端先支持 URL / 元信息录入 |
| 多数据源切换 | 只对接当前 `server` 主库元数据 API |

## 2. 产品定位与使用对象

### 2.1 定位

本产品是 **Schema Studio + Data Workspace**：

- **Schema Studio**：管理 Collection / Field / Index / Validation / Script
- **Data Workspace**：基于元数据动态渲染，管理业务记录

它不是面向最终业务用户的业务系统，而是给建模者、实施人员、开发者用的管理控制台。

### 2.2 用户角色

后端暂无权限体系，前端按**单一管理员角色**设计。后续若接入网关鉴权，仅增加登录态与只读模式，不改信息架构。

| 角色 | 典型诉求 |
|------|----------|
| 数据建模者 | 建表、配字段、配关系、配校验 |
| 实施 / 运维 | 维护表结构、同步 schema、查看记录、处理脏数据 |
| 二开开发者 | 编写钩子和自定义 API 脚本，验证语法并热加载 |

### 2.3 核心场景

1. **从零建一张业务表**：选择表类型 → 填标识与显示名 → 勾选预设字段 → 添加业务字段 → 保存并同步 → 立即录入第一条记录。
2. **维护已有表结构**：进入某表「结构」页，增删改字段、调整校验、管理索引，必要时手动 Sync。
3. **日常数据维护**：在「数据」页筛选、排序、分页、新增、编辑、批量删除记录。
4. **配置关联**：在订单表增加 `belongsTo` 客户；在记录表单中用选择器关联客户，并在详情中展开客户信息。
5. **配置校验**：给金额设置最小值；给订单写表级 CEL：「已取消订单不能改金额」。
6. **配置钩子**：在 `beforeCreate` 自动生成订单号；保存前校验脚本语法。

## 3. 范围与边界

### 3.1 系统边界

```
┌──────────────────────────────────────────────┐
│              浏览器（本产品）                   │
│  React SPA · 仅前端 · 无自建 BFF               │
└────────────────────┬─────────────────────────┘
                     │ HTTPS / JSON
                     ▼
┌──────────────────────────────────────────────┐
│              ITCodeX server                  │
│  /api/meta/*     元数据管理                   │
│  /api/c/:name/*  业务记录 CRUD + 关联         │
│  /api/custom/*   Yaegi 自定义 API（只读展示     │
│                  入口，不在本端实现脚本运行时）  │
└──────────────────────────────────────────────┘
```

### 3.2 依赖的后端能力（必须存在）

管理端功能一一映射到现有接口，不发明新协议。

| 能力 | API 前缀 |
|------|----------|
| Collection 增删改查 / 同步 | `GET/POST /api/meta/collections`，`GET/PUT/DELETE /api/meta/collections/:name`，`POST .../sync` |
| Field 增删改查 | `/api/meta/collections/:collection/fields[/:field]` |
| Index 增删查 | `/api/meta/collections/:collection/indexes` |
| Yaegi 脚本 | `/api/meta/scripts` |
| 业务记录 CRUD | `/api/c/:collection` |
| 关联操作 | `/api/c/:collection/:id/:association` |
| 统一响应 | `{ code, message, data }`；校验失败 `code=422` 且含 `fieldErrors` / `tableErrors` |

接口字段、Filter 操作符、字段类型枚举以 `docs/元数据/设计方案/05-API接口设计.md` 与 `server/api/metadata/v1` 为准。

## 4. 设计原则（现代管理端）

视觉与交互对标 Linear / Notion / Airtable / Retool 一类工具，避免传统「深蓝后台 + 密表格」观感。

### 4.1 体验原则

| 原则 | 要求 |
|------|------|
| 桌面优先 | 最小有效宽度 1280px；平板可用；不做移动端完整适配 |
| 结构即产品 | 表结构配置是一等公民，数据浏览是一等公民，二者同级切换 |
| Schema 驱动 | 所有数据表格 / 表单 / 筛选器由 Collection 元数据动态生成，禁止为某张业务表写死页面 |
| 少跳转 | 编辑字段、编辑记录优先用右侧抽屉或居中面板，列表不离开 |
| 可撤销的危险操作 | 删表、删字段、批量删记录、无条件清空必须二次确认，并写清后果 |
| 即时反馈 | 保存成功轻提示；422 错误贴到对应表单项；网络失败可重试 |
| 键盘友好 | 支持 `⌘K / Ctrl+K` 命令面板；表格支持 `Enter` 打开、`Esc` 关闭 |

### 4.2 视觉原则

- 浅色为默认主题，提供深色主题（跟随系统或手动切换）
- 中性灰底 + 单一强调色（建议靛蓝 / 青蓝，避免多色堆砌）
- 8px 间距网格；圆角 8–12px；轻阴影或边框分层，不做厚拟物
- 表格行高适中、表头吸顶、斑马纹可选、列宽可拖拽
- 空状态用短文案 + 一个主操作，不要大插画喧宾夺主
- 加载用骨架屏（列表、详情），不用整页转圈作为默认

### 4.3 信息密度

管理端允许较高信息密度，但层级要清楚：

- 一级：全局导航（数据表 / 数据 / 脚本 / 设置）
- 二级：当前 Collection 的「结构 | 数据 | 索引 | 校验 | 脚本」
- 三级：抽屉 / 对话框内的表单分区

## 5. 信息架构

### 5.1 全局导航

```
ITCodeX Meta
├── 数据表          所有 Collection 的工作室入口（默认首页）
├── 数据浏览        跨表快速进入某表的数据页（可选，可与数据表合并）
├── 脚本            全局 Yaegi 脚本列表（含表级与全局 customAPI）
└── 设置            API Base URL、主题、简单分页默认值等前端配置
```

本产品无登录页（后端无用户体系）。设置页仅保存**前端本地配置**（如 API 地址），不调用不存在的配置接口。

### 5.2 Collection 工作室（核心）

进入某一 Collection 后，顶栏固定显示：显示名、标识名、类型徽章、字段数。页内 Tab：

| Tab | 职责 |
|-----|------|
| 概览 | 表基本信息、统计（记录数 `count`）、快捷操作 |
| 结构 | 字段列表 + 添加 / 编辑 / 删除字段 |
| 数据 | 动态表格 + 筛选 + 新增 / 编辑 / 详情 |
| 索引 | 联合索引管理 |
| 校验 | 表级 CEL / 唯一约束 |
| 脚本 | 该表绑定的 Yaegi 钩子与表级自定义 API |
| 高级 | Sync、危险删除、类型专属配置（树 / 日历等） |

### 5.3 路由建议

纯前端路由，不要求后端配合。

| 路径 | 页面 |
|------|------|
| `/` | 数据表广场 |
| `/collections/new` | 创建数据表向导 |
| `/collections/:name` | 工作室（默认概览） |
| `/collections/:name/fields` | 结构 |
| `/collections/:name/records` | 数据 |
| `/collections/:name/records/:id` | 记录详情（也可做成抽屉，路由仍可深链） |
| `/collections/:name/indexes` | 索引 |
| `/collections/:name/validation` | 校验 |
| `/collections/:name/scripts` | 表级脚本 |
| `/scripts` | 全局脚本 |
| `/settings` | 设置 |

## 6. 功能需求

### 6.1 数据表广场

**作为管理员，我希望一眼看到所有业务表，并能按分类和关键词找到它们。**

#### 展示

- 视图切换：**卡片网格**（默认）/ **表格**
- 卡片内容：显示名、`name`、类型、分类标签、字段数、描述摘要
- 搜索：调用 `GET /api/meta/collections?keyword=&category=&page=&pageSize=`
- 分类筛选：从列表里的 `categories` 聚合出筛选项（前端聚合即可）
- 类型筛选：`general` / `tree` / `calendar` / `comment` / `file`

#### 操作

- 主按钮：**新建数据表**
- 卡片菜单：打开、编辑基本信息、同步结构、删除
- 空状态：说明「还没有数据表」+ 引导新建

#### 删除

- 二次确认对话框
- 文案必须说明：将删除元数据、真实数据表及其中数据
- 提供勾选项「级联删除依赖对象」（对应 `cascade`，若当前后端删除接口未暴露该 query，前端按实际接口传参；未支持则隐藏勾选）
- 系统表（`isSystem`）禁止删除，菜单禁用并提示

---

### 6.2 创建数据表向导

分步、可回退。创建成功后进入该表工作室「结构」Tab。

#### Step 1 选择类型

五种类型用大卡片展示，每张卡片含图标、名称、一句话场景：

| 类型 | 标识 | 适用 | 创建时额外配置 |
|------|------|------|----------------|
| 普通表 | `general` | 客户、订单、合同等常规业务 | 无 |
| 树表 | `tree` | 组织、分类、目录 | `options.treeParentKey`（默认 `parentId`） |
| 日历表 | `calendar` | 预约、排期、日程 | `calendarStartField` / `calendarEndField`（可稍后在结构里指定） |
| 评论表 | `comment` | 挂到业务记录的讨论 | `commentForeignKey`（可稍后指定） |
| 文件表 | `file` | 文件元信息 | 说明：本端不接对象存储，先管理元数据字段 |

不做：视图 / SQL / 继承 / 外部表。界面不出现这些入口。

#### Step 2 基本信息

| 字段 | 规则 | 对应 API |
|------|------|----------|
| 显示名称 `displayName` | 必填；业务可读，如「订单」 | 是 |
| 标识名称 `name` | 必填；字母开头，仅字母数字下划线；创建后不可改 | 是 |
| 分类 `categories` | 可选；支持输入新分类（tag 输入） | 是 |
| 描述 `description` | 可选 | 是 |
| 简单分页 `options.simplePagination` | 开关；大数据表建议开启 | 是 |
| 记录定位键 `filterTargetKey` | 默认 `id` | 是 |
| 自动生成 ID `autoGenId` | 默认开 | 是 |

`name` 由 `displayName` 自动生成拼音 / slug 的**不必做**（中文场景不可靠）。提供「根据显示名建议英文标识」为加分项，失败则让用户手填。

#### Step 3 预设字段

多选，默认全选（普通业务表建议保留）：

| 预设 | 字段名 | 说明 |
|------|--------|------|
| 主键 | `id` | 默认 Snowflake |
| 创建时间 | `createdAt` | 只读 |
| 更新时间 | `updatedAt` | 只读 |
| 创建人 | `createdBy` | 只读；无登录态时可能为空 |
| 更新人 | `updatedBy` | 只读 |

树 / 日历 / 评论 / 文件表在此步下方用提示条说明「保存后将按类型写入专属字段（如 parentId、起止时间），请勿随意删除」。

#### Step 4 初始字段（可选）

可跳过。提供「添加字段」列表，交互与 6.3 相同，随 `POST /api/meta/collections` 的 `fields` 一并提交。

也可在此步附带初始索引（`indexes`）。一期允许跳过，到索引 Tab 再配。

#### 提交

- `POST /api/meta/collections`
- 成功后可选自动 `POST /api/meta/collections/:name/sync`（默认勾选「创建后同步到数据库」）
- 失败：展示 `message`；`name` 冲突（409）高亮标识名

#### 6.3.3 字段通用配置

| 配置 | 说明 |
|------|------|
| 显示名 / 标识名 | 标识名创建后不可改（与后端一致） |
| 描述 | 表单下方帮助文案 |
| 必填 / 唯一 / 索引 | 开关 |
| 默认值 | 按类型给控件；关系字段不提供简单默认值 |
| 存储类型 `dataType` | 高级折叠区；给默认映射，允许在允许范围内改 |
| Interface 专属 options | 见下 |

**选择类专属**：选项编辑器（label / value / color），支持增删排序。

**关系类专属**：

- 目标表 `target`（从已有 Collection 选择）
- `foreignKey` / `sourceKey` / `targetKey`
- 多对多：`through` / `otherKey`

前端需做引导：belongsTo 会在本表写外键；hasMany / hasOne 外键在目标表；belongsToMany 需要中间表。用简图说明，降低配错率。

**公式**：`expression` 使用 CEL 表达式编辑器（与校验共用组件）。

**序列**：`pattern` 示例 `ORD-{YYYY}{MM}-{0000}`。

#### 6.3.4 字段校验配置

对应 `validation` + `validationRules`。

**可视化内置规则**（按类型显示）：

- 字符串：最小 / 最大 / 固定长度、正则、格式（email / url / uuid / phone）
- 数字：min / max / exclusiveMin / exclusiveMax / multipleOf / integer
- 日期：min / max
- 关系：仅必填

**CEL 规则列表**：名称、表达式、错误文案。提供模板：

- `data.phone == null \|\| data.phone.phone()`
- `size(data.name) >= 2`
- `data.amount > 0`

保存：新建 `POST .../fields`，编辑 `PUT .../fields/:field`。删除二次确认，提示可能丢失列数据。

### 6.4 表概览与基本信息编辑

- 可编辑：`displayName`、`description`、`categories`、`options`（含简单分页、类型专属键）
- 不可编辑：`name`（只读展示）
- `PUT /api/meta/collections/:name`
- 展示记录总数：`GET /api/c/:collection/count`
- 「同步到数据库」按钮：`POST /api/meta/collections/:name/sync`，用于结构变更后显式同步；成功 Toast

### 6.5 索引管理

- 列表：索引名、字段组合、是否唯一
- 新建：多选本表字段、唯一开关、可选名称
- 删除：二次确认
- API：`GET/POST/DELETE /api/meta/collections/:name/indexes`  
  删除按后端要求传 `fields` 数组

### 6.6 表级校验

对应创建 / 更新 Collection 时的 `tableValidation`（若更新接口当前只含 displayName 等基础字段，表级校验在**创建时提交**；后续若更新接口扩展再接到本页。本页一期至少：

- 展示已有 `tableValidation`（从 Collection 详情读取，若详情未返回则本 Tab 说明「请在创建表时配置，或通过后续接口更新」）
- 编辑器：联合唯一约束（字段多选）；表级 CEL（可用 `data` / `oldData` / `action`）

产品要求：**只要后端详情或更新接口暴露该字段，本页就必须可编辑。** 前端按实际响应做能力探测（字段存在则开放保存）。

### 6.7 数据工作区（记录 CRUD）

这是使用频率最高的页面。完全由当前表字段元数据驱动。

#### 6.7.1 工具栏

- 搜索：对若干字符串字段做 `$or` + `$like`（可配置搜索字段，默认所有 string/text/email/phone）
- 筛选器：可视化 Filter Builder，生成 NocoBase 风格 JSON，作为 `filter` query
- 排序：点击列表头切换升序 / 降序，对应 `sort=field` / `sort=-field`，支持最多 3 级排序
- 列设置：显示 / 隐藏列（映射 `fields` / `except`；密码列默认 except）
- 刷新、密度（紧凑 / 默认）
- 主按钮：新增记录
- 批量：勾选后出现「批量删除」

#### 6.7.2 Filter Builder

支持后端已实现操作符（与设计方案分期一致）：

| 分组 | 操作符 |
|------|--------|
| 比较 | `$eq` `$ne` `$gt` `$gte` `$lt` `$lte` `$between` `$notBetween` |
| 集合 | `$in` `$notIn` |
| 字符串 | `$like` `$notLike` `$startsWith` `$endsWith` `$includes` `$notIncludes` |
| 空值 | `$isNull` `$notNull` `$empty` `$notEmpty` |
| 逻辑 | `$and` `$or` `$not` |

交互：条件行（字段 → 操作符 → 值），可组成 AND/OR 组。高级用户可切换 JSON 源码模式。

**不做 UI**：`$col`、日期族 `$dateOn`、数组族 `$match` 等后端明确不做的操作符。

#### 6.7.3 数据表格

- 分页：`page` / `pageSize`（8 / 20 / 50 / 100）；简单分页模式下列出「下一页」而不展示精确 total（若 count 被跳过，UI 不显示总条数）
- 单元格按字段类型渲染（颜色色块、布尔开关只读、关联显示目标记录标题字段）
- 行点击打开详情抽屉；行内「编辑」「删除」
- 关系列：显示已 append 的摘要；点击可跳到目标记录
- 树表：表格支持树形展开（`parentId` / children）；筛选根节点
- 日历表：额外提供「日历视图」切换（月 / 周），事件使用配置的开始 / 结束 / 标题字段

#### 6.7.4 新增 / 编辑表单

- 抽屉宽度 480–640px；字段多时分区：业务字段 / 系统字段（系统字段编辑时只读隐藏或禁用）
- 控件由字段类型映射（见 6.3.2）
- 前端先做必填、长度、格式的即时校验；提交后以后端为准
- 422 响应：将 `fieldErrors` 映射到对应 Form.Item；`tableErrors` 展示在表单顶部 Alert
- 创建 `POST /api/c/:collection`；更新 `PUT /api/c/:collection/:id`
- 关系写入：belongsTo 提交外键或嵌套对象（以后端实际接受的 body 为准，前端封装一层）
- hasMany 子表格：支持在同一表单内增删子行（对应关联写入）

#### 6.7.5 详情

- 只读描述列表 + 「编辑」切到表单
- 「关联」分区：每个关系字段一块
  - 列表：`GET /api/c/:collection/:id/:association`
  - 添加：`POST`
  - 替换：`PUT`
  - 移除：`DELETE`
- appends：打开详情时按关系字段自动带 `appends`

#### 6.7.6 删除

| 操作 | API | 确认 |
|------|-----|------|
| 单条删除 | `DELETE /api/c/:collection/:id` | 普通确认 |
| 批量删除 | `DELETE /api/c/:collection?filter={id:{$in:[...]}}` | 列出条数 |
| 清空表 | 不带 filter 的批量删除 | **高危**：输入表标识名才能确认；并提示后端可能禁止 truncate |

#### 6.7.7 批量创建（加分 / 二期）

- 从 JSON 粘贴或 CSV 导入映射列后 `POST /api/c/:collection/batch`
- 一期可不做 UI，API 预留

### 6.8 特殊表行为

| 表类型 | 数据页增强 | 结构页增强 |
|--------|------------|------------|
| 普通表 | 标准表格 | 无 |
| 树表 | 树形表格；表单中父节点选择器（禁选自循环：不能选自己及子孙，若检测成本高则仅禁选自己，后端校验为准） | 锁定 parent / children 关系字段删除 |
| 日历表 | 表格 + 日历视图；新建可从日历格子点选日期 | 配置标题字段、开始 / 结束字段 |
| 评论表 | 按关联业务记录分组的时间线（若存在 commentForeignKey）；否则普通表格 | 提示应被业务表关系引用 |

### 6.9 Yaegi 脚本管理

#### 6.9.1 全局脚本页

- 筛选：按 Collection、钩子点
- 列：名称、表、钩子点、方法 / 路径、启用、优先级、更新时间
- 新建 / 编辑打开脚本工作室

#### 6.9.2 脚本工作室

布局：左配置 + 右编辑器（Monaco 或 CodeMirror，Go 语法高亮）。

**钩子脚本配置**

| 项 | 说明 |
|----|------|
| 名称 | 必填 |
| 绑定表 | 选择 Collection；全局 customAPI 可空 |
| 钩子点 | `beforeValidate` `afterValidate` `beforeCreate` `afterCreate` `beforeUpdate` `afterUpdate` `beforeDelete` `afterDelete` `afterCommit` `beforeFind` `afterFind` `customAPI` |
| 优先级 | 数字，越小越先 |
| 启用 | 开关；禁用走 `POST /api/meta/scripts/:id/disable`（若后端后续提供 toggle，再升级为真正开关） |

**自定义 API 额外配置**（`hookPoint=customAPI`）

- `apiPath`：如 `/c/users/:id/change-password` 或全局路径
- `httpMethod`：GET / POST / PUT / DELETE
- 页面展示最终 URL 预览：`/api/custom/...`

**编辑器**

- 提供钩子 / 自定义 API 代码模板一键插入
- 「校验语法」：`POST /api/meta/scripts/validate`，结果展示在编辑器下方
- 保存：`POST /api/meta/scripts`（创建或更新，按是否带 id）
- 删除：二次确认

**安全说明**（固定文案，设置页与脚本页各出现一次）：脚本在服务端沙箱执行，具有库表访问能力；仅可信管理员使用。本前端不执行脚本。

## 7. 关键交互与状态

### 7.1 加载与空

- 列表：骨架屏 8 行
- 接口 404：Collection 不存在 → 空页「表不存在或已删除」+ 回广场
- 接口 5xx：页内错误块 + 重试
- 无字段的新表：结构页引导添加字段；数据页允许进入但新增表单提示「请先添加字段」

### 7.2 并发与过期

- 编辑字段 / 记录提交失败（409 等）展示服务端 message
- 不实现操作变换（OT）；后写覆盖，编辑抽屉打开时拉取最新

### 7.3 校验错误呈现

```json
{
  "code": 422,
  "message": "数据校验失败",
  "data": {
    "fieldErrors": { "email": ["请输入有效邮箱"] },
    "tableErrors": ["已取消订单不能修改金额"]
  }
}
```

- 字段错误：红字在控件下，滚动到第一个错误
- 表级错误：顶部 Alert，不可忽略

### 7.4 命令面板（现代体验必做）

`Ctrl+K`：

- 搜索 Collection（按 displayName / name）
- 动作：新建表、去脚本、去设置、切换主题
- 在某表内：去结构 / 去数据 / 新增记录

## 8. 技术需求（前端）

### 8.1 技术栈（约束）

| 层 | 选型建议 | 说明 |
|----|----------|------|
| 框架 | React 18+ | 用户指定 |
| 语言 | TypeScript | 强约束，与 API 类型对齐 |
| 构建 | Vite | 开发体验 |
| 路由 | React Router | SPA |
| 状态 | TanStack Query + 轻量 UI 状态 | 服务端状态用 Query；不要把 API 数据再抄一份到全局 store |
| UI | 现代组件库（Ant Design 5 / Arco / shadcn-ui 择一） | 需支持表格、表单、抽屉、树、日期；视觉可主题化 |
| 表格 | 组件库 Table 或 TanStack Table | 列宽、虚拟滚动（记录多时） |
| 编辑器 | Monaco 或 CodeMirror 6 | 脚本与 CEL、JSON |
| HTTP | fetch 封装 | 统一 code 判断、422 解析、Base URL |
| 图表 / 地图 | 不做一期必选 | 几何点可用简单输入 |

### 8.2 工程约定

- 代码放在仓库 `web/`（与 `server/`、`client/` 并列）
- 环境变量：`VITE_API_BASE_URL`
- 开发通过 Vite proxy 转发 `/api`，避免 CORS 麻烦（后端已有 CORS，proxy 仍建议）
- 不提交密钥；不实现服务端渲染

### 8.3 API 客户端

按资源生成 typed client，与后端路径一致：

```
meta.collections.list / get / create / update / remove / sync
meta.fields.list / create / update / remove
meta.indexes.list / create / remove
meta.scripts.list / save / disable / remove / validate
data.list / get / create / update / remove / count / batch
data.association.list / add / set / remove
```

请求约定：

- 成功：`code === 0`，取 `data`
- 业务错误：抛出带 `code` / `message` / `data` 的 Error
- Query 中的 `filter` 必须 JSON 序列化后放入 URL；注意长度，超长筛选在 UI 上提示简化条件

### 8.4 动态表单引擎

核心模块 `FieldRenderer`：

```
FieldMeta → Widget
Widget 负责：展示值、编辑值、把控件值编码为 API 提交值
```

禁止按 Collection 名称写 if-else 业务页。新字段类型通过注册表扩展。
