# 多对一（belongsTo / 数据选择器）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**多对一（belongsTo）** 关系表示当前表的多条记录关联到目标表的一条记录。这是最常见的关系类型之一。

多对一关系在当前表中会创建一个外键字段，存储目标表记录的 ID。例如：订单属于一个客户，那么订单表会有一个 `customerId` 字段存储客户 ID。在界面上通常使用数据选择器（Record Picker）组件选择关联记录。

关系字段不会直接存储全部关联数据，而是通过外键在 ORM 层建立表间关系。

## 适用场景

多对一适合这些业务场景：

* 订单属于一个客户、员工属于一个部门
* 文章属于一个作者、评论属于一篇文章
* 任务分配给一个负责人、工单属于一个分类
* 多个记录共享一个上级记录的场景

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，选择「多对一」或「数据选择器」可以创建多对一关系字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。多对一通常对应 recordPicker（数据选择器），决定页面中如何选择和展示关联记录。 |
| Field display name | 字段在界面中显示的名称，比如「所属客户」「负责人」「所属部门」。建议使用业务人员能直接理解的名称。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改，只支持字母、数字和下划线，并且必须以字母开头。 |
| Target collection | 目标数据表，即当前记录关联到哪个表，比如「客户表」「用户表」。 |
| Foreign key | 外键字段名，当前表中存储目标记录 ID 的字段，比如 `customerId`、`userId`。系统会自动建议命名。 |
| Target key | 目标表的键字段，通常是目标表的主键 ID。 |
| Allow selection of existing records | 是否允许从已有记录中选择，默认开启。 |
| Allow creating new records | 是否允许在选择时直接新建目标记录。 |
| Description | 字段说明。适合写字段含义、选择规则或维护人。 |

> **注意**：关系字段配置后会影响页面区块、权限、工作流和 API 查询。删除或修改关系字段前，先确认页面和流程中是否已经在使用。

## 字段特性

| 特性 | 说明 |
|------|------|
| Field type | belongsTo（关系类型，不创建新的数据列，使用外键列）。 |
| 数据库列 | 在当前表创建外键列，存储目标记录的 ID。 |
| 页面组件 | 编辑模式使用数据选择器、下拉选择器等组件。 |
| 筛选 | 支持按关联记录筛选。 |
| 排序 | 支持按关联表字段排序（通过关联查询实现）。 |
| 关系方向 | 反向关系通常自动生成 hasMany（一对多）。 |

## 关系示例

典型的多对一关系配置示例：

* **订单 → 客户**：订单表（orders）有 `customerId` 外键，一个客户可以有多个订单，一个订单属于一个客户。
* **文章 → 作者**：文章表（articles）有 `authorId` 外键，一个作者可以有多篇文章，一篇文章属于一个作者。
* **员工 → 部门**：员工表（users）有 `departmentId` 外键，一个部门可以有多个员工，一个员工属于一个部门。

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑多对一关系字段配置。编辑关系字段主要用于调整界面展示、选择规则和联动方式。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段在界面中的显示名称。 |
| Field name | 否 | 关系字段标识创建后通常不建议修改。 |
| Target collection | 谨慎修改 | 修改目标表会影响所有关联数据。 |
| Foreign key | 否 | 外键创建后不建议修改。 |
| Selection component | 是 | 可以切换数据选择器、下拉选择器等组件。 |
| Allow create | 是 | 调整是否允许在选择时新建记录。 |
| Description | 是 | 补充字段说明。 |

> **注意**：修改目标表、外键或关系类型属于高风险操作，可能导致数据关联错误。修改前请备份数据并确认影响范围。

## 删除字段

点击字段右侧的「Delete」可以删除多对一关系字段。删除关系字段会同时删除外键列及关联关系配置。

> ⚠️ **警告**：删除关系字段会影响：
> 1. 当前表的外键列数据
> 2. 页面中已经配置的关系选择、关联展示
> 3. 工作流中使用该关系的节点和条件
> 4. API 查询和权限配置
> 
> 删除前务必确认没有业务配置依赖该关系。

## 页面配置使用

多对一关系字段在页面中有丰富的使用方式。

| 场景 | 用途 |
|------|------|
| 表单区块 | 使用数据选择器选择一条关联记录。 |
| 表格区块 | 显示关联记录的标题字段，支持跳转详情。 |
| 详情区块 | 展示关联记录信息，可以嵌套显示关联表字段。 |
| 筛选区块 | 按关联记录筛选数据，比如按客户筛选订单。 |
| 关系表字段 | 选择关联记录后，在表单中只读展示关联表的其他字段，比如选择负责人后显示其手机号、邮箱。 |

## 反向关系

创建多对一关系后，系统通常会自动在目标表创建对应的**一对多（hasMany）**反向关系。反向关系不会额外创建数据库列，通过外键反向查询即可。

例如：订单表创建 `customer` (belongsTo) 关系后，客户表会自动出现 `orders` (hasMany) 关系，可以在客户详情中查看该客户的所有订单。

## 相关链接

* 一对多（hasMany）— 反向关系，用于从主记录查看多条从记录
* 一对一（hasOne）— 一条记录关联一条记录
* 多对多（belongsToMany）— 双方都可以关联多条记录
