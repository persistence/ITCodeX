# 自动序列（Sequence / Auto increment）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**自动序列（Sequence）** 属于高级类型字段，用于按照配置的规则自动生成有序的业务编号。

自动序列字段可以生成带前缀、日期、自增序号的业务编号，如 `ORD202405120001`、`PO-2024-0001`，创建记录时自动生成，不重复，适合订单号、合同号、工单编号、申请单号等需要有规则业务编号的场景。

和数据库自增主键不同，自动序列支持前缀、日期格式、序号位数等自定义规则，更符合业务编号习惯。

## 适用场景

自动序列适合这些业务场景：

* 订单编号：如 `ORD202405120001`
* 合同编号：如 `HT-2024-0001`
* 工单编号：如 `GD2024050001`
* 申请单号、报销单号、采购单号
* 各种需要按规则生成、唯一递增的业务编号

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，在高级类型中选择「自动序列」可以创建自动序列字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。自动序列对应 sequence，创建记录时自动生成，只读。 |
| Field display name | 字段在界面中显示的名称，比如「订单编号」「合同编号」「工单编号」。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Field type | 字段在数据层的类型。通常是 varchar 字符串类型存储完整编号。 |
| Pattern | 编号生成规则（模板），支持组合固定字符、日期格式、自增序号。 |
| Starting number | 序号起始值，默认从 1 开始。 |
| Increment step | 序号步长，默认每次加 1。 |
| Number length | 序号位数，不足位数前面补零，如 4 位则 `0001`、`0002`。 |
| Reset period | 序号重置周期，可以选择不重置、按年重置、按月重置、按日重置。比如按日重置则每天序号从 0001 开始。 |
| Description | 字段说明。 |

## 编号模板规则

编号模板支持以下占位符：

| 占位符 | 说明 | 示例 |
|--------|------|------|
| 固定字符串 | 直接写固定前缀/后缀 | `ORD` → ORD |
| `{YYYY}` | 4 位年份 | `{YYYY}` → 2024 |
| `{YY}` | 2 位年份 | `{YY}` → 24 |
| `{MM}` | 2 位月份 | `{MM}` → 05 |
| `{DD}` | 2 位日期 | `{DD}` → 12 |
| `{0000}` | 自增序号，0 的个数表示位数 | `{0000}` → 0001 |

**常见编号模板示例：**
* 订单按日流水：`ORD{YYYY}{MM}{DD}{0000}` → ORD202405120001
* 合同按年流水：`HT-{YYYY}-{0000}` → HT-2024-0001
* 简单工单：`GD{0000}` → GD0001
* 月流水：`PO{YY}{MM}{000}` → PO2405001

## 字段特性

| 特性 | 说明 |
|------|------|
| 生成时机 | 记录创建时自动生成，生成后不允许修改 |
| 唯一性 | 保证生成的编号唯一不重复 |
| 递增性 | 序号严格递增，不会重复使用已生成的编号（即使删除记录） |
| 页面组件 | 只读展示，创建后不可编辑，提供复制按钮 |
| 重置规则 | 支持按年/月/日重置序号，重置后从起始值重新开始 |
| 索引 | 建议建唯一索引，保证编号唯一和查询性能 |

> **注意**：删除记录不会回退序号，比如当前序号到 0005，删除 0005，下一个还是 0006，避免编号重复。

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑自动序列字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段显示名称。 |
| Field name | 否 | 字段标识创建后不建议修改。 |
| Pattern | 谨慎修改 | 修改编号模板只影响**新生成**的编号，历史编号保持不变，会导致编号格式不一致。 |
| Starting number | 谨慎修改 | 修改起始值如果小于当前已生成序号，可能导致重复。只建议在系统上线前调整。 |
| Reset period | 谨慎修改 | 修改重置周期会影响后续编号生成，历史编号不变。 |
| Number length | 谨慎修改 | 修改序号位数影响新编号，历史编号长度不变。 |
| Description | 是 | 补充字段说明。 |

> ⚠️ **重要**：系统上线后，不要随意修改编号模板和序号规则，避免编号格式混乱或重复。

## 删除字段

点击字段右侧的「Delete」可以删除自动序列字段。删除会丢失所有已生成的业务编号，如果这些编号已经使用在打印单据、对外沟通中会造成问题。

## 页面配置使用

自动序列字段只读，不允许用户手动修改。

| 场景 | 用途 |
|------|------|
| 表单区块 | 创建表单中通常隐藏，保存后自动生成；或者只读展示，提示"保存后自动生成"。 |
| 详情/表格区块 | 只读展示编号，支持复制，常用作搜索字段。 |
| 打印模板 | 订单打印、合同打印时显示业务编号。 |
| 搜索筛选 | 通常支持按编号精确搜索或前缀搜索。 |
| 工作流 | 工作流中可以读取编号用于发送通知、生成文件名等。 |

## 注意事项

1. **编号唯一性**：即使配置了重置周期，系统也会保证编号唯一，按月重置不会和历史月份重复。
2. **并发安全**：高并发创建记录时，系统保证序号不重复，不会出现编号冲突。
3. **不要手动修改**：业务编号生成后不要允许人工修改，避免编号混乱和重复。
4. **编号长度**：预估业务量，序号位数留足余量，比如日单量过千用4位（0001-9999），过万用5位。
5. **和主键 ID 的区别**：主键 ID 是系统内部使用，连续自增，不适合对外展示；自动序列是业务编号，有业务含义，对外可见。
