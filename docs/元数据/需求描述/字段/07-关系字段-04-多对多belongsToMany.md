# 多对多（belongsToMany）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**多对多（belongsToMany）** 关系表示当前表的一条记录可以关联目标表的多条记录，目标表的一条记录也可以关联当前表的多条记录。

多对多关系需要一张中间表（through table）存储双方的关联关系。例如：文章和标签是多对多关系，一篇文章可以有多个标签，一个标签可以属于多篇文章，中间表 `articles_tags` 存储 `articleId` 和 `tagId` 的对应关系。

如果多对多关系还需要携带额外业务字段（比如角色分配时间、分配人），中间表需要建为普通业务表，通过两个一对多关系实现。

## 适用场景

多对多适合这些业务场景：

* 文章与标签、用户与角色
* 学生与课程、商品与分类
* 项目与成员、订单与优惠活动
* 双方都需要多选关联的场景

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，选择「多对多」可以创建多对多关系字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。多对多通常对应 multipleSelect 或子表格组件，决定页面中如何选择和展示多条关联记录。 |
| Field display name | 字段在界面中显示的名称，比如「标签」「角色」「参与成员」。建议使用业务人员能直接理解的名称。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Target collection | 目标数据表，比如「标签表」「角色表」。 |
| Through table | 中间表，存储双方的 ID 对应关系。系统可以自动创建中间表。 |
| Foreign key | 当前表在中间表中的外键名，比如 `articleId`。 |
| Other key | 目标表在中间表中的外键名，比如 `tagId`。 |
| Allow selecting existing records | 是否允许从已有记录中选择关联。 |
| Allow creating new records | 是否允许在选择时直接新建目标记录。 |
| Description | 字段说明。适合写字段含义或维护规则。 |

> **注意**：多对多中间表默认只存储两个外键。如果关联关系本身需要额外字段（如创建时间、备注），不要使用自动中间表，应该手动创建中间业务表。

## 字段特性

| 特性 | 说明 |
|------|------|
| Field type | belongsToMany（关系类型）。 |
| 数据库列 | 不直接在双方表创建列，通过中间表存储关联关系。 |
| 中间表 | 必须存在，存储双方外键，通常有联合唯一约束。 |
| 页面组件 | 编辑模式使用标签选择器、多选下拉、子表格等。 |
| 筛选 | 支持按关联记录包含/不包含筛选。 |
| 双向关系 | 创建后目标表也会自动生成反向多对多关系。 |

## 关系示例

典型的多对多关系配置示例：

* **文章 ↔ 标签**：文章表（articles）和标签表（tags）多对多，中间表 `articles_tags` 存储 `articleId` 和 `tagId`。
* **用户 ↔ 角色**：用户表（users）和角色表（roles）多对多，中间表 `roles_users` 存储 `userId` 和 `roleId`。
* **学生 ↔ 课程**：学生表（students）和课程表（courses）多对多，中间表 `enrollments` 存储 `studentId` 和 `courseId`。

### 带额外字段的多对多

如果关联关系本身有业务字段，例如学生选课需要记录成绩、选课时间，应该这样设计：

1. 创建中间业务表 `enrollments`（选课记录）
2. 选课记录 belongsTo 学生（studentId）
3. 选课记录 belongsTo 课程（courseId）
4. 选课记录增加成绩、选课时间字段
5. 学生 hasMany 选课记录，课程 hasMany 选课记录

这种方式比直接使用 belongsToMany 更灵活。

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑多对多关系字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段在界面中的显示名称。 |
| Field name | 否 | 关系字段标识创建后通常不建议修改。 |
| Through table | 否 | 中间表创建后不建议修改。 |
| Foreign key / Other key | 否 | 外键创建后不建议修改。 |
| Field component | 是 | 可以切换标签选择器、多选下拉、子表格等组件。 |
| Allow operations | 是 | 调整是否允许新建、选择、解除关联等操作。 |
| Description | 是 | 补充字段说明。 |

> **注意**：修改多对多关系配置属于高风险操作，可能导致已有关联数据异常。

## 删除字段

点击字段右侧的「Delete」可以删除多对多关系字段。删除时需要注意是否要同时删除中间表。

> ⚠️ **警告**：删除多对多关系会影响：
> 1. 页面中标签选择、多选组件
> 2. 权限配置中按角色/标签筛选
> 3. 工作流中的关联处理
> 4. 中间表的关联数据
> 
> 删除前确认是否需要保留历史关联数据。

## 页面配置使用

多对多关系适合标签、权限、成员等多选场景。

| 场景 | 用途 |
|------|------|
| 表单区块 | 使用标签选择器多选关联记录。 |
| 表格区块 | 以标签形式展示多个关联项。 |
| 详情区块 | 展示所有关联记录列表。 |
| 筛选区块 | 筛选包含某个标签/角色/成员的记录。 |
| 权限控制 | 用户-角色多对多是 RBAC 权限模型的基础。 |
