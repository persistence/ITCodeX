# 表 OID（Table OID）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**表 OID（Table OID）** 属于系统信息字段，主要用于继承表（Inheritance Collection）场景，区分继承自同一个父表的不同子表记录。

NocoBase 支持继承表功能：可以创建一个父表，多个子表继承父表字段，查询父表时可以同时查出所有子表记录。此时需要一个字段标识这条记录实际属于哪个子表，这个字段就是 Table OID（也叫 tableoid，源自 PostgreSQL 的系统列 `tableoid`）。

Table OID 字段存储子表的标识，让父表查询时可以区分记录实际来自哪个子表，用于多态展示、过滤、跳转详情。

## 适用场景

Table OID 是系统字段，只在使用继承表功能时才需要，主要用于：

* 继承表结构中，区分子表类型
* 父表列表查询时，知道每条记录属于哪个子表
* 根据子表类型渲染不同的操作按钮、展示不同字段
* 跳转到对应子表的详情页面
* 筛选特定子类型的记录

**不需要继承表时不需要关注这个字段**，普通表用不到。

## 什么是继承表

先简单理解继承表场景：
* 父表：比如「内容」，有公共字段：标题、正文、创建时间、创建人
* 子表1：「文章」，继承内容，额外字段：作者、分类、标签
* 子表2：「产品」，继承内容，额外字段：价格、库存、SKU
* 子表3：「公告」，继承内容，额外字段：置顶、有效期

查询父表「内容」时，可以同时查出文章、产品、公告所有记录，这时候需要一个字段区分每条记录到底是文章、产品还是公告，这个字段就是 Table OID。

## 创建配置

创建继承表的子表时，系统会自动处理，父表会自动添加 Table OID 字段用于区分子表类型。手动添加在系统信息中选择「Table OID」。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。Table OID 对应 tableOid，用于选择/展示子表类型。 |
| Field display name | 字段在界面中显示的名称，默认是「类型」或「表类型」。 |
| Field name | 字段标识名称，固定为 `__tableName` 或 `tableOid`，系统内部使用。 |
| Field type | 字符串类型，存储子表的 collection name（表标识）。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 用途 | 仅用于继承表（多表继承）场景，区分不同子表类型 |
| 自动填充 | 创建子表记录时，系统自动设置为对应子表标识，用户不能修改 |
| 可编辑性 | 只读字段，不能手动修改，一条记录只能属于一个子表，类型不能改变 |
| 页面组件 | 显示子表显示名，比如"文章"、"产品"，支持按子表类型筛选 |
| 联动 | 选择/识别类型后，动态显示对应子表的字段、操作按钮 |
| 详情跳转 | 根据类型跳转到对应子表的详情页，而不是父表详情 |

## 编辑配置

Table OID 是系统字段，配置很少，主要配置子表的显示名称。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改显示名称，通常叫「类型」「内容类型」。 |
| 子表显示名映射 | 是 | 配置每个子表在 OID 字段中显示的名称，比如 article 显示为「文章」，product 显示为「产品」。 |
| Description | 是 | 字段说明。 |

## 删除字段

继承表的父表中不建议删除 Table OID 字段，删除后无法区分子表类型，导致无法正确展示和跳转。非继承表不需要这个字段，可以删除。

## 页面配置使用

Table OID 主要在继承表的父表视图中使用。

| 场景 | 用途 |
|------|------|
| 父表列表区块 | 显示「类型」列，用标签或文字展示每条记录属于哪个子表（文章/产品/公告）。 |
| 类型筛选 | 筛选栏支持按类型筛选，只看文章，或只看产品。 |
| 操作按钮 | 根据类型显示不同操作：文章显示"编辑文章"，产品显示"编辑产品"，点击跳转到对应子表编辑页。 |
| 字段显示 | 根据类型动态显示不同列：产品显示价格列，文章显示作者列。 |
| 详情链接 | 点击标题跳转到对应子表的详情页面，而不是统一的父表详情。 |
| 统计 | 按类型分组统计，统计文章、产品、公告各有多少条。 |

## 和表选择器的区别

Table OID 和表选择器（Collection select）看起来都存表名，但用途完全不同：

| 对比项 | Table OID | 表选择器（Collection select） |
|--------|-----------|--------------------------------|
| 用途 | 继承表中系统自动维护的子表类型，固定不变 | 用户手动选择关联哪个表，用于多态关联 |
| 填充方式 | 系统自动设置，创建子表记录时确定，永远不变 | 用户表单选择，可以修改（设计上通常不修改） |
| 使用场景 | 继承表：父表查询区分子表 | 多态关联：评论、附件可以关联任意表 |
| 关系 | 标识**当前记录**属于哪个子表 | 标识**关联记录**属于哪个表，配合外键ID使用 |
| 谁来设置 | 系统自动，用户不可见不可改 | 用户选择，可以配置可选范围 |

简单说：Table OID 是给继承表用的系统字段，多态关联用表选择器字段。

## 继承表 vs 多态关联 怎么选

| 方案 | 适用场景 | 特点 |
|------|----------|------|
| 继承表 | 子表有较多不同字段，需要独立管理，但又需要统一查询展示 | 父表查所有子表，每个子表可以单独管理，字段独立 |
| 多态关联（表选择器+ID） | 通用模块（评论、附件、日志）需要关联到任意表 | 通用表可以被任意表关联，不需要预先知道会关联哪些表 |

比如内容管理有文章、产品、公告三种类型，字段差异大，适合继承表；通用评论系统可以评论任何内容，适合多态关联。
