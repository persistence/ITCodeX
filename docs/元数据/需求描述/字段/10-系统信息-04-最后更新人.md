# 最后更新人（Last updated by）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**最后更新人（Last updated by / Updated by）** 属于系统信息字段，由系统自动维护，记录是哪个用户最后修改了这条记录。

最后更新人也是系统关系字段，关联到用户表，创建普通表默认自动添加。每次修改记录时系统自动更新为当前登录用户，用户不能手动修改。和创建人配合使用，完整追溯记录的创建和最后修改责任人。

## 适用场景

最后更新人默认添加到普通表，主要用于：

* 记录最后是谁修改了这条数据，出问题知道找谁
* 按最后更新人筛选，查看某个用户最近修改的数据
* 工作列表："我最近修改的"快速找到自己编辑过的数据
* 审计追溯，知道每次改动的操作人（配合操作日志可以看完整修改历史）
* 责任认定，数据有问题时追溯最后修改人

## 创建配置

创建普通数据表时，系统默认会自动添加最后更新人字段，不需要手动创建。需要手动添加时在系统信息中选择「最后更新人」。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。更新人对应 updatedBy，是用户关联字段，只读展示。 |
| Field display name | 字段在界面中显示的名称，默认是「最后更新人」。 |
| Field name | 字段标识名称，固定为 `updatedById`（外键）和 `updatedBy`（关联对象），不建议修改。 |
| Field type | belongsTo 关系字段，关联到用户表 `users`。 |
| Target collection | 目标表固定是用户表 `users`。 |
| Auto fill | 自动填充，创建记录时初始值为创建人，每次更新记录时更新为当前登录用户。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 自动添加 | 创建普通表默认添加 |
| 字段类型 | belongsTo 关系字段，关联用户表 |
| 创建初始值 | 新建记录时，`updatedBy` 初始值等于 `createdBy`，即创建人 |
| 更新时自动更新 | 每次修改记录保存后，自动将 `updatedBy` 设置为当前操作的登录用户 |
| 可编辑性 | 用户不能手动修改，系统自动维护 |
| 页面组件 | 只读展示用户昵称/姓名，可点击跳转 |
| 筛选 | 支持按"当前用户"筛选，"我修改过的"作为筛选条件 |
| 索引 | 外键建议加索引 |

## 编辑配置

最后更新人作为系统字段，配置选项较少。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 可以修改显示名称，比如「修改人」「最后修改者」。 |
| Field name | 否 | 系统字段标识 `updatedBy` 不建议修改。 |
| Display field | 是 | 选择用户表哪个字段展示，默认昵称。 |
| Description | 是 | 添加字段说明。 |

## 删除字段

一般不建议删除最后更新人字段。删除后无法追溯最后修改人，影响审计追溯。如果不需要审计可以删除，但保留对系统影响很小，建议保留。

## 页面配置使用

| 场景 | 用途 |
|------|------|
| 表格区块 | 显示最后更新人列，和更新时间一起展示，如"张三 5分钟前修改"。 |
| 详情区块 | 元信息区域完整展示："创建人：李四，创建时间：2024-05-01；最后更新：张三，更新时间：2024-05-12"。 |
| 表单区块 | 编辑表单只读展示，不能修改。 |
| 筛选 | 可以筛选"我最近修改的"，快速找到自己编辑过的记录。 |
| 审计追溯 | 数据出问题时，先看最后更新人是谁，了解谁最后改过，再结合操作日志看具体修改内容。 |
| 工作流 | 通知可以发给最后更新人，比如"你修改的订单状态已变更"。 |

## 默认行为

* **新建记录**：`updatedBy` 初始值等于 `createdBy`，即创建人。
* **更新记录**：任何修改保存后，自动将 `updatedBy` 更新为当前登录用户，即使只改了一个字段也会更新。
* **软删除/恢复**：软删除和恢复操作也会更新 `updatedBy` 为当前操作人。
* **批量更新**：批量操作会将所有被更新记录的 `updatedBy` 设置为执行批量操作的用户。
* **用户删除**：更新人用户被删除，处理方式同创建人，通常软删除保留关联。

## createdBy vs updatedBy 对比

| 场景 | createdBy | updatedBy |
|------|-----------|-----------|
| 新建记录 | 设置为当前用户 | 和 createdBy 相同 |
| 修改记录 | 不变 | 更新为当前用户 |
| 删除记录 | 不变 | 更新为当前用户 |
| 恢复记录 | 不变 | 更新为当前用户 |
| 是否允许修改 | 不允许 | 不允许 |
| 用途 | 谁录入的，数据归属，初始责任 | 谁最后改的，最近一次修改责任 |
| 权限使用 | 常用于"只能看自己创建的" | 较少用于权限，更多用于追溯 |
| 变化 | 永远不变 | 每次修改都变化 |

## 完整审计需要什么

仅靠最后更新人只能看到谁最后改过，看不到完整修改历史。如果需要完整审计：
1. **四个基础系统字段**：创建时间、创建人、更新时间、更新人 — 提供基础追溯
2. **操作日志插件**：记录每次操作的详细信息：操作人、操作时间、修改前值、修改后值、IP地址等
3. **版本历史/活动日志**：有些场景需要记录每次修改的版本，可以回滚

普通业务场景四个系统字段足够，敏感数据需要开启详细操作日志。
