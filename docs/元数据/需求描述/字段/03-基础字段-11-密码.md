# 密码（Password）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**密码（Password）** 字段属于基础类型字段，用于存储敏感的密码类信息。

密码字段不会明文存储，系统会自动对输入值进行加盐哈希处理后保存。页面编辑时使用密码输入框，阅读模式下默认不会显示明文内容。

密码字段适用于用户密码、API 密钥等需要加密存储的敏感文本。不要用普通文本字段存储密码。

## 适用场景

密码适合这些业务场景：

* 用户登录密码
* 第三方系统密钥、Access Key
* 加密连接密码、数据库密码
* 其他需要哈希存储的敏感文本

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，在基本类型中选择「密码」可以创建密码字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。密码对应 password，决定页面中如何录入。 |
| Field display name | 字段在界面中显示的名称，比如「登录密码」「API 密钥」。建议使用明确的名称表明这是敏感字段。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Field type | 字段在数据层的类型。密码字段类型为 password，自动加盐哈希存储。 |
| Validation rules | 校验规则。通常配置最小长度、复杂度要求。 |
| Description | 字段说明。适合写密码规则、安全要求。 |

> **注意**：密码哈希是单向的，存储后无法找回明文，只能重置。如果需要可逆加密存储敏感配置（如第三方密钥），需要额外使用加密功能。

## 字段特性

| 特性 | 说明 |
|------|------|
| Field type | password |
| 数据库类型 | VARCHAR(255)，存储哈希后的字符串 |
| 存储方式 | 自动加盐哈希，不存储明文 |
| 页面组件 | 编辑模式使用密码输入框（密文显示）。 |
| 阅读模式 | 默认不显示明文，不支持查看原文。 |
| 筛选 | 不支持按密码明文筛选，只能判断是否为空。 |
| 排序 | 不支持排序，哈希值排序没有业务意义。 |
| API 返回 | 默认 API 响应中不返回密码字段值。 |

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑密码字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段显示名称。 |
| Field name | 否 | 字段标识创建后不建议修改。 |
| Validation rules | 是 | 调整密码复杂度、长度要求。 |
| Description | 是 | 补充密码规则说明。 |

> **注意**：修改密码字段不会自动重新哈希已有密码。如果修改了哈希算法或盐规则，已有用户需要重置密码才能登录。

## 删除字段

点击字段右侧的「Delete」可以删除密码字段。

> ⚠️ **警告**：删除密码字段后用户将无法通过密码登录，所有已存储的哈希数据会丢失。删除前确认是否需要迁移认证方式。

## 页面配置使用

密码字段主要用于认证和敏感配置场景。

| 场景 | 用途 |
|------|------|
| 用户注册/编辑表单 | 录入密码，通常需要确认密码输入。 |
| 个人中心 | 修改密码。 |
| 第三方系统配置 | 录入接入密码、密钥。 |
| API | 认证接口传入密码进行比对，列表和详情接口默认不返回密码字段。 |

## 安全最佳实践

1. **永远不要存储明文密码**：始终使用系统提供的密码字段类型。
2. **配置复杂度校验**：要求最小长度，建议包含字母、数字组合。
3. **HTTPS 传输**：密码输入页面必须使用 HTTPS。
4. **不返回 API 响应**：列表和详情接口不要输出密码字段，即使是哈希值。
5. **定期重置**：支持密码重置功能，不要提供密码找回功能（只能重置）。
