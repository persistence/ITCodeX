# 多对多（数组 / Belongs to many array）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**多对多（数组）** 是一种特殊的关系字段，使用数组字段直接存储关联 ID 数组实现简单多对多关系，不需要中间表。

普通多对多（belongsToMany）需要创建独立的中间关联表来存储关联关系；而数组类型多对多直接在当前表的数组字段中存储所有关联记录的 ID 数组，结构更简单，适合简单的标签、少量多选场景。

但数组方式不支持在关联关系上存储额外字段，查询性能不如中间表方式，适合数据量不大的简单多对多场景。

## 适用场景

多对多（数组）适合这些简单场景：

* 文章标签：一篇文章多个标签，标签数量不多
* 简单多选关联：选择多个负责人、多个参与人（人数不多）
* 不需要在关联上存储额外信息（不需要中间表字段）
* 数据量不大，数组不会过长的场景

如果需要存储关联的额外信息（如角色分配时间、报名状态），或者关联数据量大、需要复杂查询，使用普通多对多中间表方式。

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，在关系类型中选择「多对多（数组）」可以创建该字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。多对多数组对应选择器组件，可以多选目标表记录。 |
| Field display name | 字段在界面中显示的名称，比如「标签」「参与人」。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Target collection | 要关联的目标数据表。 |
| Field type | 字段在数据层的类型。数组类型，存储目标记录 ID 的数组，如 `[1, 5, 12]`。 |
| Multiple | 默认开启，允许多选。 |
| Allow create new | 选择时是否允许快速新建目标表记录。 |
| Description | 字段说明。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 实现方式 | 直接用数组字段存储关联 ID，不需要中间表 |
| 表结构 | 当前表多一个数组字段，不需要额外建中间表 |
| 关联存储 | 只在当前表存储 ID 数组，目标表不存反向关联 |
| 页面组件 | 多选选择器，支持搜索选择多个关联记录，支持标签展示 |
| 查询 | 包含查询可以用数组包含，但复杂查询（如反向查询"哪些文章包含某个标签"）性能不如中间表 |
| 双向关联 | 不自动维护反向关联，如果需要反向查找需要额外处理 |
| 额外字段 | 不支持在关联关系上存储额外字段（如排序、备注、加入时间） |

## 与普通多对多（中间表）对比

| 对比项 | 多对多（数组） | 多对多（中间表 belongsToMany） |
|--------|---------------|--------------------------------|
| 表数量 | 不需要额外表，当前表多一个数组字段 | 需要单独的中间关联表 |
| 额外字段 | ❌ 不支持关联上存额外字段 | ✅ 支持中间表加字段（如角色、加入时间、排序） |
| 双向查询 | ⚠️ 反向查询性能较差 | ✅ 双向查询都方便，支持索引 |
| 数据量 | 适合数组长度小（几十个以内） | 适合大量关联，性能稳定 |
| 级联操作 | 需要应用层处理 | 数据库/ORM 支持级联 |
| 事务一致性 | 更新数组时整体替换 | 可以逐行增删关联 |
| 适用场景 | 简单标签、少量多选 | 大多数多对多业务场景，推荐 |

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑数组多对多字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段显示名称。 |
| Field name | 否 | 字段标识创建后不建议修改。 |
| Target collection | 否 | 目标表创建后不能修改，已有数据会失效。 |
| Allow create new | 是 | 调整是否允许快速创建新记录。 |
| Description | 是 | 补充字段说明。 |

## 删除字段

点击字段右侧的「Delete」可以删除数组多对多字段。删除会清除当前表存储的关联 ID 数组，不影响目标表数据，但关联关系丢失。因为没有中间表，删除就是直接删除字段。

> ⚠️ **注意**：数组多对多是单向关联，如果需要双向关联要自己维护，删除字段后关联关系直接丢失，无法从目标表找回关联。

## 页面配置使用

| 场景 | 用途 |
|------|------|
| 表单区块 | 多选选择器，搜索勾选多条关联记录，标签式展示已选项。 |
| 详情区块 | 标签式展示关联记录，每个标签可以点击跳转到详情。 |
| 表格区块 | 显示关联标签，多个标签逗号分隔或标签样式展示。 |
| 筛选 | 支持筛选包含某个关联 ID 的记录。 |
| 标签场景 | 文章打标签，简单实现，标签数量不多时非常方便。 |

## 什么时候用，什么时候不用

**推荐用数组多对多：**
* 文章标签、简单分类多选
* 记录关联少量内部用户（如参与人，通常团队内人数有限）
* 快速开发原型，先跑通功能
* 不需要复杂查询和统计关联关系

**推荐用普通中间表多对多：**
* 订单和商品：需要存储购买数量、单价折扣
* 用户和角色：需要分配时间、授权人
* 学生和课程：需要成绩、选课时间
* 数据量大的场景
* 需要双向关联查询
* 需要在关联上存储额外业务字段

> 大多数业务场景推荐使用普通多对多（中间表）方式，数组多对多只适合简单场景。
