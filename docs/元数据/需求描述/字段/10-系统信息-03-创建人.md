# 创建人（Created by）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**创建人（Created by）** 属于系统信息字段，由系统自动维护，记录是哪个用户创建了这条记录。

创建人是系统字段，是一个特殊的多对一关系字段，关联到用户表（users），创建普通表时默认自动添加。创建记录时系统自动记录当前登录用户，用户不能手动修改。常用于数据权限控制（只能看自己创建的数据）、责任追溯、按创建人统计等场景。

## 适用场景

创建人是默认系统字段，主要用于：

* 记录是谁创建/录入了这条数据，责任到人
* 数据权限控制：比如普通用户只能查看和编辑自己创建的记录，部门经理可以看本部门的
* 按创建人筛选，看某个用户录入的所有数据
* 按创建人统计，统计每个人的录入量、业绩
* 工作分配："我创建的"作为一个常用筛选分类
* 审计追溯，知道数据是谁录入的

## 创建配置

创建普通数据表时，系统默认会自动添加创建人字段，不需要手动创建。需要手动添加时在系统信息中选择「创建人」。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。创建人对应 createdBy，是用户关联字段，只读展示。 |
| Field display name | 字段在界面中显示的名称，默认是「创建人」。 |
| Field name | 字段标识名称，固定为 `createdById`（外键）和 `createdBy`（关联对象），不建议修改。 |
| Field type | 特殊关系字段，多对一（belongsTo）关联到用户表 `users`，外键字段为大整数类型。 |
| Target collection | 目标表固定是用户表 `users`。 |
| Auto fill | 自动填充，创建记录时自动设置为当前登录用户 ID。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 自动添加 | 创建普通表默认添加 |
| 字段类型 | belongsTo 关系字段，关联到用户表 |
| 自动填充 | 新建记录时自动设置为当前登录用户，后端强制设置，前端传入值无效（防止伪造创建人） |
| 可编辑性 | 用户不能手动修改创建人，创建后永远不变 |
| 页面组件 | 只读展示用户昵称/姓名，可点击跳转到用户详情 |
| 筛选 | 支持"等于当前用户"、"指定用户"筛选，"我创建的"是常用筛选条件 |
| 权限 | 是行级权限控制最常用的字段 |
| 索引 | 外键字段建议加索引，按创建人筛选、权限过滤经常用到 |

## 编辑配置

创建人作为系统关系字段，配置选项较少。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 可以修改显示名称，比如「录入人」「创建者」「申请人」。 |
| Field name | 否 | 系统字段标识 `createdBy` 不建议修改，修改会影响权限等系统逻辑。 |
| Display field | 是 | 选择用户表中哪个字段用来展示，默认是用户昵称，可以选用户名、姓名、工号等。 |
| Description | 是 | 添加字段说明。 |

## 删除字段

**不建议删除**创建人字段。创建人是行级权限控制的核心字段，很多权限规则基于"创建人等于当前用户"，删除后无法实现"只能看自己的数据"这类权限控制，也失去了录入人追溯能力。

## 页面配置使用

| 场景 | 用途 |
|------|------|
| 表格区块 | 显示创建人列，展示用户昵称，点击可以查看创建人信息。筛选中常用"我创建的"快速过滤。 |
| 详情区块 | 在元信息区域展示创建人，和创建时间一起显示。 |
| 表单区块 | 创建表单不显示，编辑表单只读展示创建人信息，不能修改。 |
| 权限控制 | 最常用的行级权限规则：`createdBy = 当前用户`，实现"只能查看自己创建的数据"；扩展可以加部门、角色等条件。 |
| 数据范围 | 我的待办、我的数据、我创建的，这些常用分类都基于创建人字段。 |
| 统计分析 | 按创建人分组统计每个人创建的数据量、完成量、业绩。 |
| 工作流 | 工作流中可以读取创建人，发送通知给创建人，比如"你的订单已审批通过"。 |

## 默认行为

* **新建记录**：保存到后端时，忽略前端传入的 `createdById`，强制设置为当前登录用户的 ID。未登录用户（公开提交）创建的记录，创建人为空或系统用户。
* **更新记录**：更新记录不会修改创建人，创建人一旦设置永远不变。
* **管理员操作**：即使是管理员，默认也不能修改创建人（除非开发定制），保证审计准确性。
* **数据导入**：导入数据时可以指定创建人（比如从老系统迁移，保留原始创建人），否则导入人作为创建人。
* **删除用户**：如果创建人用户被删除，创建人字段会置空或保留 ID（取决于外键策略，通常 SET NULL）。建议用户软删除，保留历史数据关联。

## 权限规则示例

创建人最常用的行权限规则：

| 角色 | 数据范围 | 规则 |
|------|----------|------|
| 普通员工 | 只能看自己创建的数据 | `createdBy.id == currentUser.id` |
| 部门经理 | 能看本部门所有人创建的数据 | `createdBy.department.id == currentUser.department.id` |
| 管理员 | 能看所有数据 | 无限制 |
