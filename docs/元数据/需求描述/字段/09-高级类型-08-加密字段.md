# 加密字段（Encryption）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**加密字段（Encryption）** 属于高级类型字段，用于存储需要可逆加密的敏感数据。

和密码字段不同，密码字段是单向哈希（无法解密，只能校验），加密字段是对称加密存储：写入时加密，读取时自动解密给有权限的用户，数据库中存储的是密文，即使数据库泄露也无法直接看到敏感内容。

加密字段适合需要存储但需要回显查看的敏感信息，比如身份证号、银行卡号、手机号（敏感场景）、密钥配置等。

## 适用场景

加密字段适合这些业务场景：

* 身份证号、护照号等证件号码（需要查看明文但不能明文存储）
* 银行卡号、银行账号
* 敏感联系方式、私密地址
* 第三方系统密钥、Secret Key（系统内部需要读取使用）
* 商业敏感数据：成本价、供货价、合同机密条款
* 个人敏感信息（PII），满足合规要求（等保、GDPR、个人信息保护法）

## 与密码字段的区别

| 对比项 | 密码字段（Password） | 加密字段（Encryption） |
|--------|---------------------|------------------------|
| 存储方式 | 单向加盐哈希 | 对称加密 |
| 能否解密 | ❌ 无法解密，只能重置 | ✅ 有权限用户读取时自动解密 |
| 适用场景 | 用户登录密码（不需要知道原文，只需要验证） | 需要查看/使用原文的敏感数据（证件号、密钥） |
| 忘记处理 | 只能重置 | 可以解密查看（有权限） |
| 安全风险 | 哈希泄露无法反推密码 | 密钥泄露可以解密所有数据，需要保护好密钥 |

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，在高级类型中选择「加密字段」可以创建加密字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。加密字段对应 encryption，密文存储，明文展示给有权限用户。 |
| Field display name | 字段在界面中显示的名称，比如「身份证号」「银行卡号」「API密钥」。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Field type | 字段在数据层的类型。数据库中存储密文，使用 varchar 或 text 类型。 |
| Encryption algorithm | 加密算法，默认使用 AES-256-GCM 等安全对称加密算法。 |
| Masking | 脱敏展示配置，可以配置默认脱敏显示（如身份证只显示前6后4位：`110101********1234`），有权限时才能查看完整明文。 |
| Required permissions | 查看明文所需权限，可以配置只有特定角色能查看完整内容，普通用户只看到脱敏内容。 |
| Searchable | 是否支持密文搜索，开启后支持按明文搜索（需要特殊索引实现，有一定性能开销）。 |
| Description | 字段说明。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 存储 | 数据库中始终存储加密后的密文，不存明文 |
| 自动加解密 | 写入数据库时自动加密，读取时自动解密，业务代码不需要手动处理 |
| 权限控制 | 支持细粒度权限控制：无权限看不到，普通权限看脱敏，管理员权限看明文 |
| 脱敏展示 | 默认支持按规则脱敏，比如手机号 `138****1234`，银行卡 `**** **** **** 1234` |
| 审计日志 | 查看解密明文的操作会记录审计日志，满足合规要求 |
| 搜索 | 支持密文检索（取决于实现方式），不需要全表解密 |

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑加密字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段显示名称。 |
| Field name | 否 | 字段标识创建后不建议修改。 |
| Masking rule | 是 | 调整脱敏规则。 |
| Permissions | 是 | 调整哪些角色可以查看明文。 |
| Description | 是 | 补充字段说明。 |

> **重要**：加密密钥管理非常关键。密钥通常由系统配置统一管理，不要硬编码在代码中，生产环境密钥和数据库分开存储，定期轮换密钥。

## 删除字段

点击字段右侧的「Delete」可以删除加密字段。删除会丢失所有加密存储的敏感数据，密文删除后无法恢复。

## 页面配置使用

| 场景 | 用途 |
|------|------|
| 表单录入 | 输入明文，提交时自动加密存储，表单不保留明文日志。 |
| 列表/表格 | 默认显示脱敏内容，有权限用户点击"查看"按钮验证身份后展示明文，并记录审计日志。 |
| 详情页 | 同样默认脱敏，操作"显示明文"后展示，有过期时间自动恢复脱敏。 |
| API | API 默认返回脱敏内容，调用方有解密权限时才返回明文。 |
| 导出 | 敏感字段导出需要权限审批，导出记录审计日志。 |

## 安全最佳实践

1. **密钥管理**：加密密钥必须和数据库分开存储，使用环境变量或密钥管理服务（KMS），不要把密钥放在代码仓库中。
2. **最小权限原则**：只有真正需要查看明文的角色才授予明文查看权限，大部分角色只能看脱敏数据。
3. **审计日志**：所有明文查看操作必须记录日志：谁、什么时候、查看了哪条记录的哪个敏感字段。
4. **传输加密**：包含敏感字段的 API 必须使用 HTTPS，防止传输过程被窃听。
5. **字段选择**：只加密真正敏感的字段，不要所有字段都加密，影响性能和查询能力。
6. **密钥轮换**：定期轮换加密密钥，提供密钥迁移方案，老密文可以平滑解密重加密。

## 合规说明

使用加密字段存储个人敏感信息可以帮助满足以下合规要求：
* 《个人信息保护法》：个人敏感信息需要加密存储
* 网络安全等级保护（等保2.0）：敏感数据加密存储要求
* GDPR：欧盟个人数据保护条例，要求适当的技术措施保护个人数据
* PCI DSS：银行卡数据安全标准，卡号必须加密存储
