# 创建时间（Created at）

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**创建时间（Created at）** 属于系统信息字段，由系统自动维护，记录每条记录第一次创建的时间。

创建时间字段是系统字段，创建普通表时默认自动添加，用户不能手动修改值。常用于按时间筛选、排序，了解数据录入时间，做报表统计。

## 适用场景

创建时间是系统自动添加的字段，所有普通表默认都有，主要用于：

* 记录数据是什么时候创建/录入的
* 按创建时间排序，看最新录入的数据
* 按日期范围筛选某段时间创建的数据
* 统计每天/每月新增数据量
* 审计追溯，了解数据生成时间

## 创建配置

创建普通数据表时，系统默认会自动添加创建时间字段，不需要手动创建。如果需要手动添加（比如继承表或特殊表），在系统信息中选择「创建时间」。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。创建时间对应 createdAt，只读展示。 |
| Field display name | 字段在界面中显示的名称，默认是「创建时间」。 |
| Field name | 字段标识名称，固定为 `createdAt`，不建议修改。 |
| Field type | 字段在数据层的类型。日期时间类型，通常是 datetime。 |
| Timezone | 时区处理，和日期时间字段一致。 |
| Auto fill | 自动填充，默认开启，记录创建时自动设置为当前时间，不能手动编辑。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| 自动添加 | 创建普通表（General collection）时默认自动添加 |
| 自动填充 | 新增记录时系统自动设置为当前时间，不需要用户输入 |
| 可编辑性 | 用户不能手动修改创建时间，只有系统维护 |
| 页面组件 | 只读展示日期时间，支持格式化配置 |
| 排序 | 非常适合排序，默认列表通常按创建时间倒序显示最新数据 |
| 筛选 | 支持按日期范围筛选，非常常用的筛选条件 |
| 索引 | 建议加索引，因为经常用于排序和范围查询 |

## 编辑配置

创建时间作为系统字段，一般不允许修改配置。点击字段右侧「Edit」只能修改显示名称和日期格式化方式。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 可以修改显示名称，比如改成「录入时间」「创建日期」。 |
| Field name | 否 | 系统字段标识 `createdAt` 不建议修改，修改会破坏系统默认逻辑。 |
| Date format | 是 | 调整页面显示的日期时间格式。 |
| Description | 是 | 添加字段说明。 |

> **注意**：不要尝试把创建时间改成可编辑，审计字段保持系统自动维护才能保证数据准确性。

## 删除字段

点击字段右侧的「Delete」可以删除创建时间字段，但**强烈不建议删除**。创建时间是重要的审计字段，删除后无法追溯数据创建时间，很多系统功能（排序、筛选、统计、审计日志）依赖此字段。

普通表默认要求保留创建时间和更新时间字段。

## 页面配置使用

创建时间是非常常用的系统字段，在各个区块中都会用到。

| 场景 | 用途 |
|------|------|
| 表格区块 | 显示创建时间列，点击表头可以按时间排序，筛选栏中常用日期范围筛选。 |
| 详情区块 | 显示记录创建时间，放在元信息区域。 |
| 表单区块 | 创建表单通常不显示，编辑表单只读展示（灰化不可改）。 |
| 数据统计 | 按创建时间分组统计每日/每月新增数据量，做趋势图。 |
| 工作流 | 工作流中可以读取创建时间判断记录是否超期，比如创建超过N天未处理自动提醒。 |
| 权限 | 可以根据创建时间控制数据范围，比如只能查看自己本周创建的数据。 |
| 导出 | 导出数据时默认包含创建时间，方便外部分析。 |

## 默认行为

* **新建记录**：保存到数据库时，自动设置 `createdAt = NOW()`，由服务端时间决定，不接受客户端传入的值（防止篡改）。
* **更新记录**：更新记录时不会修改创建时间，创建时间一旦设置永远不变。
* **删除/恢复**：软删除记录再恢复，创建时间保持原始值不变。
* **数据导入**：导入数据时，如果没有提供创建时间，使用导入时间作为创建时间；导入时允许指定创建时间保留历史数据的原始时间。

## 为什么不能修改创建时间

创建时间是重要的审计字段：
1. 保证数据追溯的准确性，知道数据是什么时候进入系统的
2. 防止人为篡改时间伪造数据
3. 作为排序和统计的基准字段，保持稳定
4. 满足合规审计要求，操作可追溯

如果确实需要记录业务发生时间（比如订单实际下单时间可能和录入时间不同），建议单独加一个业务日期字段，而不是修改系统创建时间。
