# JSON

> 来源：NocoBase 文档整理
> 整理时间：2026-09-02

## 介绍

在 NocoBase 中，**JSON** 属于高级类型字段，用于存储 JSON 格式的结构化数据。

JSON 字段可以存储任意结构的 JSON 对象或数组，适合存储结构不固定、扩展属性、第三方 API 响应、配置参数、嵌套结构数据等，不需要预先定义字段结构。

如果数据结构固定、需要查询统计，建议拆分成多个普通字段或使用关联表；JSON 字段适合灵活的半结构化数据存储。

## 适用场景

JSON 适合这些业务场景：

* 扩展属性：不同类型记录有不同属性，如商品的不同规格参数
* 第三方系统回调数据、API 响应原始报文
* 配置参数、偏好设置、JSON 格式的规则配置
* 嵌套结构数据，如收货地址（虽然可以拆字段，但嵌套更方便时）
* 标签数组、动态选项列表
* 结构经常变化，不方便加字段的半结构化数据

## 创建配置

在数据表的「Configure fields」页面中，点击「Add field」，在高级类型中选择「JSON」可以创建 JSON 字段。

| 配置 | 说明 |
|------|------|
| Field interface | 字段的界面类型。JSON 对应 json，提供 JSON 编辑器。 |
| Field display name | 字段在界面中显示的名称，比如「扩展属性」「原始响应」「配置参数」。 |
| Field name | 字段标识名称，用于 API、权限、工作流等内部引用。创建后通常不再修改。 |
| Field type | 字段在数据层的类型。如果数据库支持原生 JSON 类型（MySQL 5.7+、PostgreSQL）使用 JSON 类型，否则使用 TEXT 存储。 |
| Default value | 默认值，可以配置默认的 JSON 对象结构。 |
| JSON Schema | 可选，配置 JSON 结构校验规则，校验输入的 JSON 格式是否符合要求。 |
| Validation rules | 校验规则，如是否必须是对象、必须包含哪些字段。 |
| Description | 字段说明。适合说明 JSON 结构约定。 |

## 字段特性

| 特性 | 说明 |
|------|------|
| Field type | json 或 text（取决于数据库） |
| 存储内容 | 合法的 JSON 格式，可以是对象 `{}`、数组 `[]`、字符串、数字、布尔值、null |
| 页面组件 | 编辑模式提供 JSON 编辑器，支持语法高亮、格式化、校验；阅读模式格式化展示 |
| 格式校验 | 编辑时自动校验 JSON 语法错误，不能保存非法 JSON |
| 查询 | 支持 JSON 路径查询（需要数据库支持 JSON_EXTRACT 等函数） |
| 索引 | 支持对 JSON 内部路径建虚拟列索引（不同数据库支持程度不同） |

## 编辑配置

创建后，点击字段右侧的「Edit」可以编辑 JSON 字段配置。

| 配置 | 允许编辑 | 说明 |
|------|----------|------|
| Field display name | 是 | 修改字段显示名称。 |
| Field name | 否 | 字段标识创建后不建议修改。 |
| Default value | 是 | 修改默认 JSON 结构，只影响新记录。 |
| JSON Schema | 是 | 调整结构校验规则。 |
| Description | 是 | 补充 JSON 结构说明。 |

## 删除字段

点击字段右侧的「Delete」可以删除 JSON 字段。删除会丢失所有已存储的 JSON 数据。

## 页面配置使用

| 场景 | 用途 |
|------|------|
| 表单区块 | 使用 JSON 编辑器编辑，支持语法高亮、自动格式化、错误提示，也可以提供表单界面编辑 JSON 内部字段（需要自定义组件）。 |
| 详情区块 | 格式化缩进展示 JSON，支持折叠/展开节点。 |
| 表格区块 | 默认显示 JSON 预览，点击可以展开查看完整内容。 |
| API | REST API 直接按 JSON 结构返回，不需要额外序列化。 |
| 工作流 | 工作流节点可以解析 JSON 字段，提取内部字段值用于逻辑判断或赋值。 |

## JSON 使用建议

**适合使用 JSON 的场景：**
* 数据结构差异大，每种类型都有不同属性
* 只需要存储，很少需要按内部字段筛选或统计
* 第三方原始数据，需要原样保存方便排查问题
* 配置类数据，整体读取整体写入

**不适合使用 JSON，建议拆字段/建关联表的场景：**
* 需要经常按 JSON 内部字段筛选、排序、统计
* 内部字段需要参与权限控制、工作流条件判断
* 结构固定且不会频繁变化
* 需要和其他表关联

> 提示：很多新手会滥用 JSON 字段，把所有字段都塞到一个 JSON 里，导致后续查询统计困难。结构固定时优先使用普通字段。

## JSON 字段示例

**商品扩展属性示例：**
```json
{
  "color": "黑色",
  "size": "XL",
  "weight": 1.2,
  "specifications": {
    "cpu": "i7",
    "memory": "16GB",
    "storage": "512GB SSD"
  }
}
```

**用户偏好设置示例：**
```json
{
  "theme": "dark",
  "language": "zh-CN",
  "notifications": {
    "email": true,
    "sms": false,
    "push": true
  },
  "sidebarCollapsed": false
}
```

**第三方回调原始数据示例：**
```json
{
  "transaction_id": "wx20240512xxxx",
  "out_trade_no": "ORD202405120001",
  "amount": 99.00,
  "payer": {
    "openid": "oxxxx",
    "name": "张三"
  },
  "paid_at": "2024-05-12T10:30:00Z"
}
```

## 数据库支持

| 数据库 | 原生 JSON 支持 | JSON 查询函数 |
|--------|---------------|---------------|
| MySQL 5.7+ | ✅ 支持 JSON 类型 | ✅ JSON_EXTRACT 等函数 |
| PostgreSQL | ✅ 支持 JSON 和 JSONB 类型（推荐 JSONB） | ✅ 丰富的 JSON 操作符和函数 |
| SQLite | ⚠️ 存储为 TEXT | ⚠️ 有限 JSON 函数支持 |
