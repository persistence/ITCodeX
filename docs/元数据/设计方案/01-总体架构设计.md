# ITCodeX 元数据模块 - 总体架构设计

> 版本: v1.0
> 日期: 2026-09-03
> 技术栈: GoFrame + CobaltDB(嵌入式) + CEL-Go + Yaegi

## 1. 设计目标

### 1.1 核心目标
- 提供类 NocoBase 的动态元数据管理能力
- 支持运行时动态创建/修改/删除数据表和字段
- 内置丰富的字段类型（文本、数字、日期、关系、媒体等）
- 支持单字段和多字段联合校验（CEL-Go）
- 支持通过 Yaegi 进行二次开发，无需重新编译
- 嵌入式部署，无需独立数据库服务

### 1.2 非功能目标
- 高性能：元数据缓存 + 嵌入式数据库直接访问
- 高可用：嵌入式架构无单点故障
- 易扩展：插件化字段类型、校验规则、操作符
- 易二开：Yaegi 脚本热加载，支持业务逻辑定制

## 2. 技术选型

| 组件 | 技术选择 | 说明 |
|------|----------|------|
| Web框架 | GoFrame v2 | 高性能 Go Web 框架，提供路由、中间件、ORM 等完整能力 |
| 数据库 | CobaltDB | 嵌入式数据库，支持 SQL，零依赖部署 |
| 校验引擎 | cel-go | Google Common Expression Language，支持单字段/多字段联合校验 |
| 脚本引擎 | Yaegi | Go 语言解释器，支持运行时动态执行 Go 代码，用于二开 |
| 主键生成 | Snowflake / UUID / NanoID | 支持多种主键策略 |
| JSON处理 | encoding/json + gjson | 高效 JSON 处理 |

## 4. 核心模块职责

### 4.1 Database 模块
- 管理 CobaltDB 嵌入式数据库连接
- 维护 Collection 和 Field 注册表
- 提供数据库同步、迁移能力
- 管理全局事件监听
- 注册自定义字段类型、操作符、Repository

### 4.2 Collection 模块
- 描述数据表元信息（名称、字段、索引、类型等）
- 管理字段的增删改查
- 同步表结构到 CobaltDB
- 提供 Repository 实例
- 支持表类型：普通表、树表、日历表、评论表、文件表

### 4.3 Field 模块
- 描述字段元信息（名称、类型、校验规则等）
- 支持多种字段类型（基础、选择、媒体、日期、关系、几何、高级、系统）
- 字段类型映射到 CobaltDB 数据类型
- 字段级校验规则配置
- 关系字段处理（belongsTo/hasOne/hasMany/belongsToMany）

### 4.4 Repository 模块
- 提供统一的数据 CRUD 接口
- 支持 Filter 查询（$eq/$gt/$in/$and/$or 等操作符）
- 支持排序、分页、字段选择
- 支持关联数据查询和操作
- 事务支持
- 事件钩子（beforeCreate/afterCreate 等）

### 4.5 Validation 模块（CEL-Go）
- 单字段校验：必填、长度、范围、格式、正则等
- 多字段联合校验：跨字段表达式校验
- 自定义校验函数注册
- 编译后的 CEL 程序缓存
- 校验错误信息国际化

### 4.6 Yaegi 模块
- Go 脚本解释器初始化和管理
- 脚本沙箱环境（导出安全的 API）
- 脚本热加载和缓存
- 内置 CRUD 钩子点（before/after create/update/delete）
- 自定义 API 路由注册
- 脚本错误处理和日志

## 5. 元数据表结构（系统表）

|------|------|------|
| id | bigint | 主键(Snowflake) |

| display_name | varchar(255) | 显示名称 |
| table_name | varchar(255) | 数据库实际表名 |
| type | varchar(50) | 表类型：general/tree/calendar/comment/file |
| description | text | 描述 |
| categories | json | 分类标签 |
| options | json | 表配置选项（排序、简单分页等） |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |
| created_by | bigint | 创建人 |
| updated_by | bigint | 更新人 |

### 5.2 fields - 字段定义表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键(Snowflake) |

| display_name | varchar(255) | 显示名称 |
| type | varchar(50) | 字段Interface类型 |

| interface_type | varchar(50) | 界面类型 |

| sort | int | 排序 |
| is_system | boolean | 是否系统字段 |
| is_required | boolean | 是否必填 |
| is_unique | boolean | 是否唯一 |
| default_value | text | 默认值 |
| description | text | 描述 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

### 5.3 indexes - 索引定义表
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |

| options | json | 脚本配置 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

## 6. 启动流程

```
1. 初始化 CobaltDB 嵌入式数据库
   ├─ 打开/创建数据库文件
   └─ 配置连接池参数

2. 同步系统元数据表
   ├─ 创建 collections 表
   ├─ 创建 fields 表
   ├─ 创建 indexes 表
   └─ 创建 yaegi_scripts 表

3. 注册内置字段类型
   ├─ 基础字段：string/text/integer/bigInt/float/double/decimal/boolean
   ├─ 日期字段：date/time/datetime/timestamp
   ├─ 高级字段：uuid/nanoid/json/jsonb/encrypt/formula/sort/sequence
   └─ 关系字段：belongsTo/hasOne/hasMany/belongsToMany

4. 注册内置查询操作符
   ├─ 比较：$eq/$ne/$gt/$gte/$lt/$lte/$in/$notIn
   ├─ 逻辑：$and/$or/$not
   ├─ 字符串：$like/$startsWith/$endsWith/$includes
   └─ 数组：$match/$anyOf/$empty

5. 加载元数据到内存
   ├─ 从 collections 表加载所有表定义
   ├─ 从 fields 表加载所有字段定义
   └─ 在内存中构建 Collection 和 Field 对象

6. 同步业务表结构
   └─ 根据元数据同步 CobaltDB 中的业务表

7. 初始化 Yaegi 脚本引擎
   ├─ 加载启用的 Yaegi 脚本
   ├─ 编译脚本并缓存
   └─ 注册自定义 API 路由

8. 启动 HTTP 服务
   ├─ 注册元数据管理 API
   ├─ 注册动态 CRUD API
   └─ 注册 Yaegi 自定义 API
```

## 7. 关键设计原则

### 7.1 元数据缓存
- Collection 和 Field 定义在启动时加载到内存
- 元数据变更时同步更新缓存和数据库
- 提供缓存失效和刷新机制

### 7.2 事件驱动
- 完整的生命周期事件：before/after sync/validate/create/update/save/destroy
- 支持全局事件监听和单表事件监听
- Yaegi 脚本通过钩子点介入事件流程

### 7.3 安全沙箱
- Yaegi 脚本运行在沙箱环境中
- 只暴露安全的 API 给脚本
- 脚本执行超时控制
- 资源使用限制（内存、CPU）

### 7.4 扩展性
- 字段类型可通过 RegisterFieldType 扩展
- 查询操作符可通过 RegisterOperator 扩展
- Repository 可自定义扩展
- CEL 自定义函数可注册
