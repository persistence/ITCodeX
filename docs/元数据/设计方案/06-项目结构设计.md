> 版本: v1.2
> 日期: 2026-09-05
> **代码根路径**: `d:\code\ITCodeX\server`
> **Go Module**: `itcodex/server`

### 1.2 禁止事项

- 不要新建 `logic/` 承载业务
- 不要手写或手改 `dao/`、`model/do/`、`model/entity/` 中由 `gf gen dao` 生成的文件
- 不要为动态业务表执行 `gf gen dao`
- 系统表写入使用 DO，不要用 `g.Map`

## 2. 路由注册

### 2.1 启动（internal/cmd）

```go
func mainFunc(ctx context.Context, parser *gcmd.Parser) error {
    s := g.Server()
    s.Use(ghttp.MiddlewareHandlerResponse)

    metaSvc := metadata.MustBootstrap(ctx)

    s.Group("/api", func(group *ghttp.RouterGroup) {
        group.Middleware(ghttp.MiddlewareCORS, bizctx.Ctx)
        group.Group("/meta", func(meta *ghttp.RouterGroup) {
            meta.Bind(controller.NewMetaV1(metaSvc))
        })
        registerDynamicCRUD(group.Group("/c"), metaSvc)
        group.Group("/custom", func(custom *ghttp.RouterGroup) {
            custom.ALL("/c/{collection}/*action", middleware.YaegiCollectionAPI(metaSvc))
            custom.ALL("/global/*action", middleware.YaegiGlobalAPI(metaSvc))
        })
    })

    enhanceOpenAPIDoc(s)
    s.Run()
    return nil
}
```

OpenAPI 使用框架默认响应：

```go
openapi.Config.CommonResponse = ghttp.DefaultHandlerResponse{}
openapi.Config.CommonResponseDataField = `Data`
```

### 2.2 静态 Meta：g.Meta

```go
// api/metadata/v1/collection.go
type CollectionListReq struct {
    g.Meta   `path:"/collections" method:"get" tags:"Meta" summary:"列出 Collection"`
    Keyword  string `p:"keyword"`
    Category string `p:"category"`
    Page     int    `p:"page" v:"min:1"`
    PageSize int    `p:"pageSize" v:"min:1|max:200"`
}
type CollectionListRes struct {
    List  []CollectionItem `json:"list"`
    Total int              `json:"total"`
}
```

Controller 只做参数转发：

```go
func (c *ControllerV1) CollectionList(ctx context.Context, req *v1.CollectionListReq) (res *v1.CollectionListRes, err error) {
    return c.meta.ListCollections(ctx, req)
}
```

### 2.3 动态 CRUD：显式路由

`/api/c/:collection` 的表在运行时才存在，**不要**为每张业务表生成 `g.Meta`。在 `/c` 组注册：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/{collection}/count` | 计数（须在 `/{id}` 前） |
| POST | `/{collection}/batch` | 批量创建 |
| GET/POST/PUT/DELETE | `/{collection}` | 列表 / 创建 / 批量更新 / 批量删除 |
| GET/PUT/DELETE | `/{collection}/{id}` | 单条 |

请求参数仍可用 Query/JSON 解析；记录体是 `map[string]interface{}`，由元数据 + CEL 校验。

## 3. 数据访问约定

### 3.1 系统表（DAO / DO）

```go
_, err := dao.Collections.Ctx(ctx).Data(do.Collections{
    Name:        input.Name,
    DisplayName: input.DisplayName,
    Type:        "general",
}).Insert()
```

- 未赋值的 DO 字段为 `nil`，ORM 忽略
- 不要手动写 `CreatedAt` / `UpdatedAt`
- 软删用 `Delete()`，不要手写 `deleted_at`

### 3.2 业务表（Repository）

动态 `CREATE` / `ALTER` 与行 CRUD 留在 `service/metadata` 的 Repository，使用参数化 SQL 与 Filter 翻译。行数据用 `map[string]interface{}` 是领域需要，不是对「系统表禁止 g.Map」的违反。

## 5. 启动顺序

```
1. 加载配置
2. 初始化日志
3. g.DB() 连接 MySQL
4. Bootstrap 元数据服务
   ├─ 同步系统表
   ├─ dao 加载元数据到内存
   ├─ 注册字段类型和操作符
   ├─ 同步业务表（动态 DDL）
   └─ 加载 Yaegi 脚本
5. 注册中间件与路由
6. 启动 HTTP
```

## 6. 与当前代码的差距

| 设计目标 | 当前 `server`（过渡） |
|----------|----------------------|
| `internal/service/metadata` | 业务仍在 `internal/logic/metadata` |
| `api/metadata/v1` + `g.Meta` + Bind | 手写 `ghttp` 路由函数 |
| 系统表 dao/do | 系统表也用 `database/sql` |
| `internal/cmd` + `main.go` | 已落地：入口为 `server/main.go` |

实现迁徙按 `README` 分期进行，不必一次搬完；新代码按本目录落地。
